Sovereign Control Panel Private Preview

Sovereign Control Panel (SCP) is a unified Azure portal experience for viewing, managing, and evaluating sovereignty posture across tenant resources. It aggregates sovereignty signals into a centralized dashboard.

This repository contains the onboarding documentation for the SCP Private Preview.

Important: Sovereign Control Panel is currently in an invite-only private preview.

What SCP does in Private Preview

Private Preview focuses on the View Experience — the ability to create and view Sovereign control across your Azure resources. In this phase, SCP is read-only. It does not update or auto-remediate resources.

Module 2: Register the Resource Provider

How-to Guide | Step 2 of 7

Because Sovereign View is a new resource type in preview, you must register its resource provider, Microsoft.Sovereign, in your Azure subscription before you can create a Sovereign View.

You only need to do this once per subscription.

Prerequisites

  • Complete Module 1: Prerequisites and Roles
  • Use a subscription whose ID you shared in the onboarding form

Register Microsoft.Sovereign

# Step
1 Sign in to the Azure portal.
2 On the Azure portal menu, search for and select Subscriptions.
3 Select the subscription ID you shared in the onboarding form where you want to create the view.
4 On the left menu, under Settings, select Resource providers.
5 Search for Microsoft.Sovereign to register.
6 Click on the resource provider and select Register.
Tip: To maintain least privilege in your subscription, register only the resource providers that you intend to use.

Registering with the resource provider allows you to create Sovereign view resources in this subscription. You only need to do this once per subscription.

Module 3: Create a Sovereign View

How-to Guide | Step 3 of 7

After the resource provider is registered, you can create a Sovereign View resource. You can create it only on the subscriptions (in an allowlisted tenant) that you provided in the onboarding form.

Prerequisites

  • Complete Module 2: Register the resource provider
  • Have Contributor + Resource Policy Contributor or Owner on the target subscription

Start the create experience

# Step
1 In the Azure portal's top search bar, type Sovereign, then select Sovereign Control Panel.
2 On the overview page, select Create View.

Complete the Basics tab

# Step
1 The Create view page opens with the Subscription and Resource group prefilled.
2 On the Basics tab, fill in the details:
  • Subscription — Choose the subscription where you want to create this Sovereign view resource (the same subscription you registered)
  • Resource group — Create new or select an existing resource group
  • Name — Enter a descriptive name for your Sovereign view
  • Region — Choose the region for your resource
3 Select Next to move to the Scope tab.

Select the scope

# Step
1 On the Scope tab, select + Add resources.
2 You can choose a Management Group (to include all subscriptions under it) or/and one or more specific Subscriptions to be included in this Sovereign view. Use the UI controls to select your resources.
3 After selecting the resources, select Add.
4 On the Scope page, you can remove subscriptions or management groups you don't want to include by selecting them and clicking remove. Once your selection is confirmed, select Next.

Configure the policy initiative

The Sovereign view focuses on specific dimensions or control sets (e.g., Data Residency, Encryption at Transit & Rest, etc.) relevant to data sovereignty. All your scoped resources will be evaluated against these policy initiatives. Data Residency is a mandatory policy initiative, the rest are optional.

# Step
1 On the Policy initiative tab, review the settings:
  • Data Residency (Geography) — In the current preview, the default value of Europe will be available.
  • Encryption at rest — Select this if you want to evaluate your resources for this policy initiative.
  • Encryption in transit — Select this if you want to evaluate whether your resources enforce TLS 1.2 or higher for data in transit.
  • Controlled Network Exposure — Select this if you want to evaluate your resources against the two policy initiatives defined in this dimension.
2 Check "I confirm" to allow SCP to proceed with creating the resource and associated policy assignments. All policy assignments are created in non-enforcing mode. Azure Sovereign View does not block any operations or auto-remediate; it only reports sovereign control data. When you're finished, select Next to review and create the Sovereign View.
Tip: To learn more about any Azure policy, see its definition on the Azure Policy page in the portal.

Review and create

# Step
1 On the Review + create tab, verify all configuration details (scope, name, region, etc.). Then check the box and select Create to deploy the Sovereign View resource.
2 After clicking the Create button, within a few seconds the deployment will be completed, and your Sovereign view resource will be generated.

The deployment completes within a few seconds, and your Sovereign View resource is created.

Module 4: Assign Managed Identity Roles

How-to Guide | Step 4 of 7

After you create a Sovereign View, you must grant its managed identity read access to your environment so it can collect data and generate the sovereignty control report.

The Sovereign View resource has a system-assigned managed identity. For each subscription and management group in the view's scope, assign this identity the Reader and Resource Policy Contributor roles.

Prerequisites

  • Complete Module 3: Create a Sovereign View
  • Have Owner or User Access Administrator permission to assign Azure roles

Confirm the identity assignment permission

# Step
1 After a successful deployment, select Go to resource to open the Sovereign View resource.
2 On the left side, click Properties under Settings and check if you have the identity assignment permission as Yes. This means you have the permission to assign the required role to the managed identity.
Note: Assign Reader and Resource policy contributor to the Identity: For each subscription and management group that you included in the Sovereign view scope, you must assign this managed identity both roles.

Option 1: Assign roles manually

# Step
1 In the Sovereign View, select Properties, then select a management group or subscription in scope, one at a time.
2 Click Access control (IAM), and then click + Add and select Add role assignment from the dropdown.
3 Search for Reader, and select it.
4 In Assign access to, choose User, group, or service principal, then search for and select the Sovereign View's managed identity (it appears as a service principal).
5 Select Review + assign to finalize the role assignment.
6 Repeat the steps above to also assign the Resource Policy Contributor role to the same managed identity.
7 After adding the identity, select Review + assign to confirm.
8 Select Review + assign to finalize the role assignment.

Repeat this process for each subscription and management group in your Sovereign View scope. This grants the Sovereign View permission to read the configuration of resources in those scopes.

Option 2: Assign roles by using the PowerShell script

The assign-roles.ps1 script grants the view's managed identity the Reader and Resource Policy Contributor roles across the in-scope subscriptions so it can collect compliance data.

# Step
1 Open the Sovereign View in the Azure portal.
2 Select PowerShell at the top of the portal to open Azure Cloud Shell in PowerShell mode.
3 In Cloud Shell, open Manage files > Upload, and upload the assign-roles.ps1 script.
4 Run the script with ./assign-roles.ps1. It verifies your sign-in, installs the resource-graph extension (one time), and lists the available Sovereign Views.
5 Select the target view — Enter the number of your Sovereign view. The script retrieves the view's Managed Identity Principal ID and displays its scope — the subscriptions and management groups in scope.
6 Confirm the role assignments — The script checks existing assignments and shows which required roles (Reader and Resource Policy Contributor) are missing for each scope item.
7 Roles assigned — The script assigns Reader and Resource Policy Contributor to the managed identity on each in-scope subscription and prints a summary of the results.
Tip: Run ./assign-roles.ps1 -DryRun first to preview the assignments without making any changes.

Report generation

Once the above role assignments are in place, the Sovereign view will begin collecting data. An initial scan will be completed within 24 hours.

Verify Access

If the report does not generate or remains empty, double-check that the managed identity indeed has Reader rights on all relevant scopes (e.g., if you selected a management group containing multiple subscriptions, ensure the identity has Reader access at the management group level).

Module 5: View the Sovereignty Control Report

How-to Guide | Step 5 of 7

Use this module to review the Sovereign View report after data collection completes, including dimension-level summaries and resource-level compliance details.

Prerequisites

  • Complete Module 4: Assign managed identity roles
  • Allow up to 24 hours after the role assignments for the initial scan to complete

Read the report

After data collection is complete, your Sovereign View resource presents a sovereignty control report in the Azure portal.

Area What you see
Resource compliance list From the Encryption in transit card, select View resources out of policy. The resources page opens with the Encryption in Transit filter applied so you can review resource-level compliance.
Policy details Select a resource to open the details pane. Review the Encryption in Transit result and Azure Policy information to understand the gap and plan remediation.

Manage the resource

The Sovereign View resource periodically refreshes its data (for example, every 24 hours, or as policies trigger scans). You don't need to re-run anything manually — check the resource page for the last scan time and current compliance status.

Module 6: Delete a Sovereign View

How-to Guide | Step 6 of 7

This guide explains how to delete a Sovereign View resource and what happens when you remove it.

Prerequisites

  • An existing Sovereign View resource (see Module 3: Create a Sovereign View)
  • Contributor or Owner rights on the subscription, and Resource Policy Contributor permission on the in-scope subscriptions and management groups

Delete the resource

You can delete the Sovereign View resource from the Azure portal by selecting Delete on the resource's page, just like any other Azure resource.

What happens when you delete

Deleting the resource will:

  • Remove its managed identity
  • Delete any stored data
  • Not affect any of your other resources or configurations
  • Simply remove the Sovereign View resource itself

If you need the view again later, recreate the resource and reassign permissions. See Module 3: Create a Sovereign View and Module 4: Assign managed identity roles.

Module 7: Troubleshooting and Support

How-to Guide | Step 7 of 7

Use this guide to resolve common onboarding issues, understand the preview's limitations, and find out how to get help.

Limitations and known issues (preview)

Sovereign View is in Private Preview. Be aware of these known constraints:

No editing or updates

Modifying an existing Sovereign View's settings or scope after creation isn't supported in preview. The resource is effectively read-only after creation. To change the scope or settings, delete the resource and create a new one with the desired configuration.

Review only, no enforcement

All evaluations are non-enforcing. Sovereign View doesn't block any operations or auto-remediate; it only reports sovereign control data. The underlying Azure policies are in Audit mode.

Support scope

Preview support is currently limited to targeted customers. Work with the Microsoft product team or your account team by email or through the Microsoft Teams channel.

Troubleshooting

Sovereign View not visible or not creating

Make sure the resource provider is registered (see Module 2) and that your account has the necessary permissions. If you can't find Sovereign Control Panel in the portal search, verify that your tenant is allowlisted for the preview.

Sovereign View fails creation with Quota Exceeded Error

For Sovereign Views to fetch the required report data, Sovereign Control Panel needs to assign some policies in Audit mode to the Subscriptions/Management Groups which are added to the scope. Azure has a limit on the number of policy assignments per scope.

Find the scopes in the failing Sovereign View which are close to or above this limit. You can use the REST API to check current policy assignments.

To resolve:

  • Either remove them from the scope
  • Delete any existing policy assignments which are not needed to create some headroom

Once done, please try creating the Sovereign View again. Reach out to the SCP contact if the issue persists.

Scope doesn't list all expected subscriptions or management groups

This usually indicates a permission issue. The portal lists only resources where you have Contributor + Resource Policy Contributor or Owner access. If a subscription or management group is missing, check your permissions with your subscription administrator.

The report is empty or incomplete

This can happen when the managed identity lacks access to part of your scope. Revisit the role assignments for the identity (see Module 4) and ensure that it has both Reader and Resource Policy Contributor roles assigned to all relevant scopes.

Understanding "Not Applicable" or "Not in definitions" statuses

These statuses indicate that a particular sovereign control found no applicable resources in the evaluated scope, or that the control is conditional and wasn't evaluated for your scenario. Many "Not Applicable" results are expected; they simply mean that a particular control doesn't apply to your environment.
